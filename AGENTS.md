## Project structure

Code is organized per feature module under `src/modules/<domain>/`:

| File | Purpose |
|------|---------|
| `<domain>.domain.ts` | Domain types (no DB/audit fields) |
| `<domain>.schema.ts` | Zod/OpenAPI request & response schemas |
| `<domain>.repository.ts` | Drizzle data access; extends `BaseRepository` |
| `<domain>.service.ts` | Business rules; throws chanfana exceptions |
| `<domain>.routes.ts` | Chanfana endpoints + route registration |

Shared code (container, errors, http, types, auth, time) lives in `src/shared/`, DB plumbing in `src/db/`. A new domain is a new folder in `src/modules/`, wired through `src/routes/index.ts` and `src/shared/container.ts`.

Current modules:

| Module | Purpose |
|--------|---------|
| `pegawai` | `users` table = pegawai. Auth endpoints (`/api/auth/*`) plus admin-only CRUD. |
| `bidang` | Master data `bidangs`, admin-only CRUD. |
| `pangkat-golongan` | Master data `pangkat_golongans`, admin-only CRUD. |

Module-local tunables (enums, patterns, thresholds) live in `<domain>.constants.ts`; cross-cutting app constants stay in `src/shared/config.ts`.

## Database (D1 + Drizzle)

Schema lives in `src/db/schema.ts`, migrations in `drizzle/`.

| Command | Purpose |
|---------|---------|
| `npx drizzle-kit generate` | Generate a migration after schema changes |
| `npm run migrate` | Apply migrations locally (`wrangler d1 migrations apply my-first-worker-db --local`) |
| `npx wrangler d1 migrations apply my-first-worker-db --remote` | Apply migrations remotely |

Migrations are applied manually, not as part of `wrangler deploy`.

### Timestamps

| Kind | Unit | Helper |
|------|------|--------|
| Audit columns (`*_at`) | epoch **milliseconds** | `auditCreate()` / `auditUpdate()` / `auditDelete()` |
| Business/transaction dates | epoch **seconds** | `nowSeconds()` / `toSeconds()` / `fromSeconds()` in `src/shared/time.ts` |

Never store ISO strings or SQLite datetime text, and never mix units in one table.

### Transactions

- D1 has no interactive `BEGIN`/`COMMIT`, and Drizzle's `db.transaction()` is not supported on the D1 driver. The only atomic primitive is `db.batch([...])`.
- Any write action that touches more than one statement or table MUST go through a single batch (use `BaseRepository.writeBatch`). Never issue sequential awaited writes that must all succeed together.
- Single-statement writes are already atomic; do not wrap them in a batch.
- Reads are never wrapped in a batch/transaction.
- Foreign keys are enforced. Every FK MUST declare the referential action explicitly: `.references(() => other.id, { onDelete: "restrict", onUpdate: "restrict" })`. Never rely on the default `no action`.
- Referential actions only cover hard deletes of the parent row and changes to the referenced key (`id`). They do NOT block updates to other columns, and they do NOT fire for soft deletes. Because deletes in this project are soft and ids never change, the database constraint is a safety net — the service still needs its own guard (e.g. `countLivePegawai`) and must return 409 when a master row is still in use on delete.
- Validate referenced rows in the service before insert/update. If a query still reaches the database and violates a constraint, `handleError` (`src/shared/errors.ts`) maps D1's `FOREIGN KEY constraint failed` / `SQLITE_CONSTRAINT` to a 409 "Constraint violation" response instead of a 500.

### Search (FTS5 trigram)

- Text search goes through an FTS5 virtual table using the `trigram` tokenizer, maintained by triggers on the source table. Example: `pegawai_fts` indexes `users.nama` and `users.nip`.
- Search query params MUST require at least 3 characters (Zod `.min(3)`). Reject shorter input with a validation error; never fall back to `LIKE '%term%'`, which is a full scan on D1.
- Query with `MATCH` and always quote/escape the user input. Filter `deleted_at IS NULL` with `liveWhere(...)`; the FTS index is not filtered by itself.
- FTS DDL cannot be generated by drizzle-kit. It lives in a hand-written migration (`drizzle/0001_pegawai_fts.sql`). Keep that file when squashing migrations, and run it after the table it indexes exists.

### Audit columns

Every table MUST include the shared audit columns by spreading `...auditColumns` from `src/db/audit.ts`:

| Column | Type | Meaning |
|--------|------|---------|
| `created_at` | integer NULL | epoch milliseconds |
| `updated_at` | integer NULL | epoch milliseconds |
| `deleted_at` | integer NULL | epoch milliseconds; soft-delete marker |
| `created_by` | integer NULL | user id |
| `updated_by` | integer NULL | user id |
| `deleted_by` | integer NULL | user id |

Rules:

- All audit columns are nullable and have no database default. Values are written pre-persist by the application through `auditCreate()` / `auditUpdate()` / `auditDelete()`.
- Audit timestamps are epoch milliseconds (`Date.now()`), never ISO strings or SQLite datetime text.
- `*_by` are nullable integers, the same type as the user id. Auth exists now, so repositories receive the current pegawai id (`c.get("user")!.id`) and pass it to the audit helpers; seeded rows use `null` because there is no actor.
- Audit columns are internal only. Never add them to domain types (`src/modules/*/*.domain.ts`), Zod/OpenAPI schemas (`src/modules/*/*.schema.ts`), endpoint payloads, or API responses. Repositories map DB rows to domain objects and must drop audit fields.
- Deletes are soft: set `deleted_at` / `deleted_by` instead of removing rows. Repositories extend `BaseRepository` (`src/db/baseRepository.ts`) and every read (list, get, update target) MUST filter through `liveWhere(...)`, which adds `isNull(table.deletedAt)`.
- Unique constraints MUST be partial unique indexes scoped to live rows and case-insensitive: `uniqueIndex("...").on(sql`lower(${table.column})`).where(sql`${table.deletedAt} IS NULL`)`. Never use `.unique()` on a column, otherwise a soft-deleted row keeps blocking reuse of that value.
- Exception: `bidangs.bidang` and `pangkat_golongans` are intentionally NOT unique (parity with the legacy app). Do not add unique indexes there; duplicates are only prevented by the idempotent seed script, not by the database.
- Queries that filter by a unique text column (get, update, delete target) MUST compare with `lower(column)` too (e.g. `eq(sql`lower(${table.slug})`, value.toLowerCase())`). Otherwise a row stored with different casing won't match the uniqueness semantics of the index.
- Queries must never use `SELECT *` (bare `.select()` / `.returning()`). Repositories project only the columns needed for the domain/DTO and exclude audit columns, which are internal and never exposed. Applies to both `select()` and `returning()`.

## Authentication

Pegawai are the users: credentials and profile live on the `users` table (`nip`, `nama`, `password_hash`, `role`, `status`, ...). Auth endpoints are in `src/modules/pegawai/pegawai.routes.ts`:

| Endpoint | Purpose |
|----------|---------|
| `POST /api/auth/login` | Verify `nip` + password and set the auth cookie |
| `POST /api/auth/logout` | Clear the auth cookie |

Rules:

- There is NO public register endpoint. Pegawai are created by an admin through `POST /api/pegawai`, and the first admin is inserted by `npm run seed`.
- Passwords are hashed with PBKDF2-SHA256 (100k iterations, random salt) via `src/modules/pegawai/pegawai.password.ts`. The stored format is `pbkdf2_sha256$<iterations>$<salt>$<hash>` so the iteration count can be raised later.
- `password_hash` is internal only. It never appears in domain types, Zod/OpenAPI schemas, or API responses.
- On create, an empty or omitted `password` defaults to the NIP. On update, an empty or omitted `password` keeps the current one.
- NIP is the login identifier and is unique case-insensitively (partial unique index on `lower(nip)` where `deleted_at IS NULL`); all lookups compare with `lower(nip)`.
- JWT helpers (`src/shared/auth.ts`) sign HS256 tokens with `JWT_SECRET` and a 7 day expiry, stored in an `HttpOnly`, `Secure`, `SameSite=Lax` cookie named `access_token`. Read the identity from that cookie instead of accepting tokens from headers.
- The token carries the identity (`id` as `sub`, `nip`, `nama`, `role`). Route handlers get the current pegawai from `c.get("user")` with no extra request, so **never** add a `/me` endpoint or a per-request user lookup.
- `JWT_SECRET` is an environment secret. Set it locally in `.dev.vars` and remotely with `wrangler secret put JWT_SECRET`. Never commit the real value.
- Protection is default-deny: `src/index.ts` wires `app.use("*", requireAuth)`, so every route requires auth unless listed in `publicRoutes` (`src/shared/auth.ts`) as `"METHOD /path"`. Currently public: login, logout, and the docs routes (`/`, `/redocs`, `/openapi.json`, `/openapi.yaml`). New public endpoints MUST be added there explicitly.
- Docs routes are development-only: `src/index.ts` short-circuits them unless `ENVIRONMENT=development` (set in `.dev.vars`; `wrangler.jsonc` sets `production`). In production they return `{ "success": true }` with 200 and act as a health check.
- Role checks use `requireRole("admin")` from `src/shared/auth.ts`, applied centrally in `src/routes/index.ts` before route registration. The role comes from the token, never from a DB query. Admin-only: `/api/pegawai`, `/api/bidang`, `/api/pangkat-golongan` (collection and detail).
- Inactive pegawai (`status = non_aktif`) are rejected at login with 401. A token issued before deactivation stays valid until it expires; that is an accepted trade-off.
- The guard returns 401/403 JSON responses directly instead of throwing chanfana's `UnauthorizedException`/`ForbiddenException`: `ApiException` is not a Hono `HTTPException`, so in middleware it would surface as a 500 through `app.onError`.
- Chanfana drops headers set via `c.header()` when `handle()` returns a plain object. Any route that sets or clears a cookie MUST return `c.json(...)` so the `Set-Cookie` header survives.

## Object storage (R2)

Object storage is configured but not used by any module yet. When a module needs uploads, follow these conventions:

- Uploads go straight from the browser to R2 through presigned URLs (`aws4fetch`); file bytes never stream through the Worker. Presigned URLs always target the real bucket, so do not use the R2 binding for reads/deletes.
- `R2_ACCOUNT_ID` and `R2_BUCKET` are vars in `wrangler.jsonc`; `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` are secrets (`.dev.vars`, `wrangler secret put ...`).
- Keys are server-generated as `<prefix>/<uuid>` with no extension. Never accept an arbitrary key from the client. The content type is read from the object (e.g. via `HEAD`), not encoded in the key.
- If a per-object size limit is needed, sign `content-length` via `allHeaders: true`: R2 does not support presigned POST policies, so R2 itself is the only upload-time size enforcement.
- Download URLs are presigned GETs with a short TTL, regenerated on every response instead of stored.
- Local dev uses a separate bucket (`<prod-bucket>-dev`) set in `.dev.vars`, so dev and prod keep one code path without sharing data.
- Bucket CORS lives in `r2-cors.json` and is applied with `npm run r2:cors` / `npm run r2:cors:dev`. It must allow the SPA origins for `GET`/`PUT`/`HEAD` with the `Content-Type` header, otherwise browser uploads fail at preflight.

## API conventions

- Create, update, and delete endpoints return `{ success: true }` only; they never echo the created/updated/removed entity. The identity needed for auth (e.g. pegawai for JWT signing) may be kept internally but must not be exposed in the response.
- List endpoints use cursor pagination via `src/shared/pagination.ts`. Query params: `cursor` (id of the last item, optional), `cursor_value` (sort value of the last item; required when `sort` is not `id`), `sort` (per-module enum, default `id`), and `order` (`asc`/`desc`, default `desc`). The `page` param is gone.
- Pagination is keyset, never offset: the repository adds a `(sort_column, id)` condition, orders by the same columns, and fetches `PAGE_SIZE + 1` rows. Page size is defined once in `src/shared/config.ts` (`PAGE_SIZE`, default 20) — change it there, not per repository. There is no `limit` query param.
- List responses include top-level `next_cursor` (id or `null`), `next_cursor_value` (sort value or `null`), and `has_more`. They are `null`/`false` when there is no next page. The FE must echo `next_cursor` and `next_cursor_value` on the next request.
- Sortable columns must be `NOT NULL` (all current ones are), so keyset comparison has no null-ordering edge case. Tie-break is always `id` in the same direction. Per module: `pegawai` = `id`/`nama`/`nip`; `bidang` = `id`/`bidang`; `pangkat-golongan` = `id`/`jenjang`/`pangkat`/`golongan`/`ruang`.
- `cursor` + non-`id` sort without `cursor_value` is a validation error (400). `cursor_value` without `cursor` is ignored.
- Request bodies are `z.strictObject`: unknown properties are rejected. Updates are true PUT: every non-password field is required, and nullable fields must be present (as `null` when empty).
- API payloads use snake_case (`nip`, `nama`, `bidang_id`, `pangkat_golongan_id`, `kategori_jabatan`, `kategori_kebutuhan_jam_pelatihan`); domain types and Drizzle columns stay camelCase internally.
- Empty strings for nullable text are normalized to `null` before persisting. Empty/missing `password` means "default to NIP" on create and "keep current" on update.
- Pegawai list supports `search` (min 3 chars, FTS5 trigram over `nama`/`nip`) plus filters `role`, `status`, `bidang_id`, `pangkat_golongan_id`, `kategori_jabatan`, `kategori_kebutuhan_jam_pelatihan`.

## Local Explorer (Debugging & Inspection)
When running `npx wrangler dev`, a Local Explorer API is available for inspecting and debugging local Workers, bindings, and storage state. The API base URL is printed in the terminal when the dev server starts.

Key endpoints (relative to the dev server URL):

| Endpoint | Description |
|----------|-------------|
| `GET /cdn-cgi/local/explorer/api/local/workers` | List local Workers and their bindings |
| `GET /cdn-cgi/local/explorer/api/storage/kv/namespaces` | List KV namespaces |
| `GET /cdn-cgi/local/explorer/api/d1/database` | List D1 databases |
| `GET /cdn-cgi/local/explorer/api/r2/buckets` | List R2 buckets |
| `GET /cdn-cgi/local/explorer/api/workers/durable_objects/namespaces` | List Durable Object namespaces |
| `GET /cdn-cgi/local/explorer/api/workflows` | List Workflows |
| `POST /cdn-cgi/local/explorer/api/local/observability/query` | Run a read-only SQL query (SELECT/WITH only) over captured request traces and console logs. Tables: `spans`, `logs` (read attributes via `json(attributes)`). Example: `curl -X POST <base>/cdn-cgi/local/explorer/api/local/observability/query -H 'Content-Type: application/json' -d '{"sql":"SELECT service, name, outcome, duration_ms FROM spans WHERE parent_id IS NULL LIMIT 20"}'` |
| `POST /cdn-cgi/local/explorer/api/local/observability/clear` | Clear all captured traces and logs |

If the routes above don't cover what you need, fetch the full OpenAPI schema (large - use only as a last resort): `GET /cdn-cgi/local/explorer/api`

Use the Local Explorer to debug issues by inspecting storage state (KV keys, D1 rows, R2 objects, DO storage), viewing Worker bindings, and querying request traces and logs captured during the dev session.
